# Integrations

[Back to Uptime Goblin](../README.md) · [Configuration](configuration.md)

A source has two addresses: the destination opened by a click and the API/exporter queried by the Uptime Goblin server. Add a separate source for every independently monitored instance. Uptime Goblin does not install exporters, discover credentials, import historical graphs from another application, or control services.

**Native** means an application-specific adapter. **Exporter** means Prometheus text exposition, which Uptime Goblin reads directly without a Prometheus server. **Bookmark** means a link without metrics or alerts. A Website check proves HTTP reachability, not full application health.

| Type | Method and credentials | Collected measurements and limits |
|---|---|---|
| Proxmox | Native cluster API; dedicated token `user@realm!token=secret`, recommended `PVEAuditor` scope | Node/guest CPU, memory, uptime; running guests, online nodes and storage used/capacity. Per-guest detail covers the 128 lowest VMIDs; totals, nodes and storage always include everything. Optional `nodeName` limits a card to one node and its guests/storage; blank collects the visible cluster, where CPU, memory and nodes online use online nodes only and an offline node's per-node, guest and storage readings are left out (`guests_total` still counts every guest). Selected-node availability is `node_online` (1 online, 0 offline). Hypervisor data does not provide every guest filesystem/process/service measurement. |
| Linux | `node_exporter`; optional Bearer token if your protected endpoint supports it | CPU, memory, load, uptime (measured against the host clock from `node_time_seconds`), filesystem use/free space and network rates. CPU/network rates require two readings. Network rates add up physical interfaces only, each counted once: loopback, bridges (vmbr, br-, docker, virbr), veth/tap/tun, VPN (wg, tailscale, zt), bonds, VLAN sub-interfaces and similar virtual devices are left out unless nothing else is reported. First 200 eligible filesystems; virtual/temporary filesystem types are filtered. |
| Windows | `windows_exporter`; optional Bearer token at a protected endpoint | CPU (idle, user and privileged time), physical memory, logical disk use/free space and network rates. CPU/network rates require two readings; network rates leave out Hyper-V vEthernet, tunnel and VPN adapters. First 200 logical disks. Available fields depend on enabled exporter collectors/version. |

When one of the limits above leaves readings out (a library that is too large, more than 512 measurements, 128 Proxmox guests, 64 UniFi devices, 20,000 UniFi list entries or 100 pages, 50 UniFi sites, entries without a usable name or ID, 256 network interfaces, 200 filesystems or Windows volumes, or CrowdSec alerts over 16 MiB or at 1,000), the card and **Test connection** show a short note saying what was left out or capped. The other readings continue.

Fixtures cover representative adapter responses and failure cases; they are not certification of every service release. Use **Test connection** against your own version and permissions before enabling recurring monitoring. An account/token that works may still have more privileges than Uptime Goblin needs.

## Simple website checks

Choose **Website check** as the monitoring method on any source to check a Docker-hosted service or other HTTP(S) endpoint. Use the website address reachable from the Uptime Goblin server; no exporter or application API token is needed. The probe never sends native credentials. Saved credentials are kept while the check stays on the same server, and cleared when its address moves to a different server, so they can never follow the source elsewhere. A separate source is needed to collect native statistics and website checks at the same time.

By default, 200–399 responses count as reachable. Redirects are not followed, so a login redirect checks only the responding front door. Set accepted statuses to `200-299` to reject redirects, or explicitly include `401`/`403` when an authentication challenge is expected. HEAD is optional for services that support it; GET is the default. Network/TLS failures and unexpected status codes use ordinary collection-failure alerts and history gaps. This check establishes reachability, not container resource usage or full application health.

## Least privilege and connectivity

Create dedicated service credentials where the application supports them. Restrict them to the resource/site/instance and read operations needed. Some media applications expose one powerful API key rather than a read-only key: protect that key and network path accordingly. Read-only behavior in Uptime Goblin does not reduce privileges encoded in a token.

For Proxmox, assign the auditing role at the intended resource scope with propagation where needed. If token privilege separation is enabled, both the user and token permissions must allow the read. Test visible resources before broadening scope.

To monitor several Proxmox hosts, create a card for each exact, case-sensitive `nodeName`. They can all collect through any reachable API endpoint in the same cluster while opening different destination URLs. The chosen node resource must be visible to the token. If it is reported offline, Uptime Goblin emits `node_online: 0` and omits stale runtime measurements; a `node_online` rule below 1 detects this separately from API connection failures. An empty node name preserves cluster-wide collection.

Use the official [node_exporter](https://github.com/prometheus/node_exporter) and [windows_exporter](https://github.com/prometheus-community/windows_exporter) documentation for installation and collector options. Restrict exporter reachability to Uptime Goblin or place authentication/TLS in front. Uptime Goblin does not require SSH root access to poll an exporter.

Docker's daemon socket grants powerful host access. Do not mount it into Uptime Goblin or expose the full daemon API. Permit only the inventory GET through a separately secured proxy; Uptime Goblin has no Docker-specific username/password or client-certificate support. Native Cosmos/AMP credentials likewise need only the monitoring reads their adapters use.

## UniFi authentication and sites

An Integration API key takes priority if saved. Key mode uses the local Network Integration API, not the cloud Site Manager API. An empty `siteId` collects all visible sites; a populated value is a site UUID. Verify the key's actual role/scope independently: availability of an API key does not guarantee read-only privileges.

For local mode, leave the key empty and enter a dedicated local account with **Network View Only** access. Use the HTTPS console root (for example `https://unifi.example.com`), without `/proxy/network` or another path. `siteId` is the legacy site name, usually `default`; blank means `default`, not all sites. Cloud sign-in and interactive MFA are unsupported. See Ubiquiti's [local management](https://help.ui.com/hc/en-us/articles/28457353760919-UniFi-Local-Management) and [API overview](https://help.ui.com/hc/en-us/articles/30076656117655-Getting-Started-with-the-Official-UniFi-API).

Local mode logs in at `/api/auth/login`, then reads `stat/health`, `stat/device` and `stat/sta` under `/proxy/network/api/s/<site>/`. Those native endpoints may change between releases. Session cookies stay in server memory and are reused until UniFi rejects them or their token expires; timeouts and other errors keep the session, so retries do not sign in again. Sessions are renewed shortly before their token expires, and if renewal fails the still-valid session keeps being used. If UniFi answers a sign-in with HTTP 429, Uptime Goblin waits for its Retry-After period (one minute by default) before signing in again. AMP, Nginx Proxy Manager and CrowdSec sessions follow the same rules. TLS verification is mandatory. Local mode reports state 0 as disconnected and state 1 as online; transitional states are not mislabeled disconnected, and their retained device telemetry is omitted.

To switch from a saved key, clear credentials and save, then enter the local username/password. Confirm that the console hostname resolves to the intended reachable interface while preserving certificate hostname validation.

## Exporter and JSON mappings

See [mapping examples](../examples/README.md). `path` is a JSON dot path or an exact Prometheus metric name. `scale` defaults to 1. Prometheus `labels` select exact values (compared as the exporter sends them, line breaks and direction controls included; at most 200 characters, no NUL); matching series are **summed**, so filter gauges to avoid unintentionally combining devices. A label filter or a step of a JSON path holding U+FFFD that matches nothing as sent is compared with the exporter's text made whole, half of a surrogate pair read as U+FFFD. A match as sent comes first. When the comparison made whole matches texts the exporter sent differently (two different halves), the mapping reads nothing rather than their sum or the first of them, and the source shows a note; a Prometheus mapping can add a filter on another label in which those series differ, and otherwise the exporter must send whole text. Uptime Goblin 1.5 makes such a half in a saved mapping (a `\u` escape 1.4.x accepted) U+FFFD at startup and cannot tell which half it was, so the mapping keeps its 1.4.x reading while the exporter sends neither U+FFFD itself nor another half at that place. If it sends U+FFFD there, the series or member sent with U+FFFD is read instead. Missing or nonnumeric values are omitted. Built-in Linux/Windows readings can be supplemented with mappings.

Synology/WireGuard need mappings because exporter schemas vary. The API base URL cannot contain a query/fragment, and a custom endpoint path cannot contain query syntax. An exporter requiring target/module query parameters therefore needs a fixed internal proxy endpoint or a differently configured exporter. Do not place credentials in a URL.
